# 0.2.6-t8.4 更新与恢复修复

本版处理自动更新等待、设置页阻塞及上游同步诊断问题。应用仍基于上游 v0.2.6，配套节点为 1.3.3、协议为 1；原生引擎、模型格式和视频/语音分析算法不变。

## 行为修复

| 场景 | 本版行为 |
|---|---|
| 下载、校验或复制耗时较长 | 显示当前组件、字节或文件进度，输出写入更新日志 |
| 网络中断或响应截断 | 最多尝试三次；在同一次更新内验证续传范围，不把完整响应追加到旧片段；仍核对完整 SHA256 |
| 启动器接受请求后回复丢失 | 保持更新等待状态并重连，明确的服务器拒绝才恢复操作并报错 |
| 更新后台失败 | 保留错误结果与日志，旧启动器退出后尝试重开设置页 |
| 回退备份校验较慢 | 在后台校验，不持有页面状态锁；失败后原启动器保持可用 |
| 无效回退 ID 或失败按钮状态 | 拒绝非法 ID，避免误触普通更新；失败后恢复可用的回退按钮 |
| 模型切换中配置暂不可读 | 状态页返回诊断，已知后端配置仅用于展示；保存和启动继续严格读取真实文件 |
| Windows 大量文件路径检查 | 直接读取系统属性，逐级检查仍在，覆盖超长路径及失效目录链接 |
| 同步资产预检、查询或网络失败 | 生成新的阶段诊断，避免复用旧冲突分支 |
| 测试候选修改 GitHub workflow | 导出 Git bundle、基准/目标提交与 SHA256 供审查，不依赖默认令牌的 workflow 写权限 |

安装和回退继续检查目录归属、用户文件冲突、文件摘要和进程状态。模型路径、API 设置、语音缓存、视频任务、日志及用户文件不进入受管替换清单。

## 开发验证与范围

修复开发阶段完成应用主回归 2,421 项、最后补充的页面/交接 57 项、网页 63 项、安装配置 836 项及节点兼容 479 项验证。范围存在重叠，不相加作为唯一测试总数。最终设置页修复由独立启动的页面/交接与网页回归覆盖。正式发行提交的检查结果以本版 Release 为准。

完整环境在隔离目录实际升级并离线回退，逐文件摘要及八类私有测试数据均核对通过。该验证使用本地暂存的完整环境，不代表已完成互联网下载后全程升级，也不包含新的 GPU 推理测量。

本机 Windows 11 专业版 10.0.26200、i7-14700KF、Windows PowerShell 5.1，在同一 G 盘完整包中交替检查前 1,000 条路径两轮：旧实现分别为 1.4933 / 1.3674 秒，新实现为 0.0886 / 0.0825 秒。这只是路径检查的差异，不能推算整体更新加速倍数。

## 上游与旧版升级

在隔离源码副本同步上游 v0.2.9 时仍有 14 处语义冲突。同步中止后 HEAD、工作区及 T8 修改保持原样。本版没有整体迁入 v0.2.9，也没有把诊断保存成功视作已经合并。后续迁移需要逐项审查和原生编译验证。

整合包用户更新读取 T8 正式 Release，与上游同步 CI 独立。旧版程序首先使用旧版更新器完成这次升级，新版的进度和网络恢复能力随后生效。旧页面无响应时，查看更新窗口和 `logs/update-helper.log`；退出当前整合包启动器后可运行 `UPDATE-PORTABLE.bat`。更早的仅支持完整 ZIP 的客户端按[发行类型迁移](UPDATING-T8.md#发行类型迁移)使用完整新版环境，并选择原模型目录。

主模型、MTP、语音权重与私有 roadmap 不进入发行包；VisionReady 保留视觉权重和配置。ASR、模型及浏览器聊天记录的原有使用方式沿用。
