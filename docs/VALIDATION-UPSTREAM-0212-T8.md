# 上游 v0.2.12 迁移验收

本地开发候选 **0.2.12-t8.1**，固定上游 `146df3c468739147f520ac3816de806f71232571`。源码、Control 和六种官方 Windows 引擎为 **0.1.58**。正式公开版本以 GitHub Release 为准；本轮仅更新开发分支。

## 同步与保留

合入上游 0.2.11、0.2.12 的工具调用、并行结果匹配、低显存启动、请求计时、图像方向、引擎稳定性、DFlash2 和聊天存储改进。`features.json` 与上一正式版逐项相同，共 52 项，未以删除功能解决合并冲突。

保留 T8 EXE、无主模型设置页、模型 ID 复制和自动切换、带密钥局域网服务、原生视频时序输入、完整时长分段、可选语音转录及时间戳对白融合、进度恢复、组件更新与离线恢复。独立节点仍为 **1.3.3 / 协议 1**。桌面 Host 源码继续同步，便携版入口仍为 T8 EXE 和网页。

本轮未下载主模型、MTP、ASR 模型或 drafter；只准备固定摘要的引擎组件与 Python 依赖。私有 roadmap、个人配置和模型目录不进入 Git 或候选包。

## 复现与修正

- **自定义模型 API 无法保存。** 原“应用”按钮在长表单底部，1280×720 和 390×800 均超出可见范围；直接填写模型 ID 还会禁用保存。改为顶部常驻“保存”，同时保存尚未点“添加模型”的 ID，错误也在顶部显示。真实浏览器分别以中英文完成保存和刷新读回，无 JavaScript 错误。使用临时 Host 配置和本地模拟 API。
- **便携网页 API Key 缺少明确保存入口。** 增加“保存”，保留自动保存。真实浏览器验证写入和刷新读回；存储不可写时继续明确提示不能持久化。
- **低显存重试丢失取消和启动时限。** 修正首次懒加载回落参数、VRAM 回落的参数传递，并保留原取消事件和剩余 READY 时限。分卡回落继续传递超时，取消或未确认退出直接返回。使用真实测试子进程先失败、再验证修复。
- **旧回答误停新模型。** 真实子进程复现旧流关闭后向替换引擎发送 STOP，以及卸载后的清理异常。写入、停止、排空和请求队列清理绑定原进程，避免影响后来启动的引擎。
- **工具结束后打断仍显示缓冲文本。** 真实浏览器强制将工具结果、后续文本和结束事件放在同一次读取中，复现多余文本。收到缓冲区及处理工具结果后立即检查取消信号。保留已完成工具结果，停止后续文本并发送待发消息。另以可见的中断状态判断正确性，避免用 TCP 关闭时机断言快速服务。
- **MCP 别名误判歧义。** 同一声明工具的 Responses 别名曾被当作不同工具，调用退化成文本。按规范工具身份去重，真实重名歧义仍拒绝。
- **Windows 文件和模型目录。** 新聊天目录曾保留 SYSTEM/Administrators 显式权限；改用当前用户精确 DACL，验证中文、引号路径及嵌套继承。Documents 重定向目录曾因 ENOENT 静默回到旧模型目录；先解析已有父目录，再建立缺失部分，继续保留既有目录和模型文件。

Python 运行环境同步到上游要求的 **Pillow 13.0.0**，核对官方 PyPI wheel SHA256。旧 12.3 环境不能直接套用新源码。已在隔离环境验证导入和依赖版本，并检查 8 个扩展的 PE 依赖；所需 VC 库由便携 Python 提供。这不是全新 Windows 系统的验收声明。

完整旧包升级还发现并修复了启动问题：旧执行器成功替换文件后留下空的 `pillow-12.3.0.dist-info`，标准元数据查询选中空目录并返回 `None`，依赖检查随后报错。新版保留正常版本查询和严格版本约束，仅在无效元数据遮蔽时查找有效记录；有效旧版本不会被跳过。新执行器还会整理自己运行环境中缺少 METADATA 且完全为空的旧目录，不删除文件或跟随链接。已在真实失败目录验证修复，并在完整候选环境中重现该目录结构，确认 EXE 能打开无模型设置页。相关 23 项专项通过。

另修复两处构建问题：视觉程序已编入 7 类架构，清单却沿用官方的 4 类，模拟 sm_80/90/100 时确实误回落 CPU；现按实际编译架构写入，模拟选择和原生构建专项共 65 项通过。Trellis overlay 重复配置原先重写相同内容，导致无谓重编；现在验证重复生成的字节和修改时间都不变，完整构建再次执行时 Ninja 显示无需重编。三份原生产物的字节摘要保持一致。

## 实机与升级

RTX 4060 Ti 16 GB、128 GB 内存，使用已有 SC117 IQ3_S。源码目录和完整环境目录均以仅系统 PATH 完成文字、图片、原生 GENIV 四帧输入结合转录对白的真实请求。模型正确识别红色图片，并按两段转录时间描述红色到蓝色的变化。使用受限缓存和内存保护，测试后停止本次服务并释放模型。

CPU ASR 使用已有 Q4_K_M GGUF，未命中缓存，输出两段输入时间线对白，耗时 8.015 秒。该转录与四帧测试一起用于链路验证；这不是自然视频质量或速度基准。

使用真实正式版 `0.2.10-t8.1` 客户端和执行器，将完整本地组件安装为 `0.2.12-t8.1`，再由新客户端执行离线恢复。新版 12996 个、旧版 12986 个受管文件逐项 SHA256 一致，9 类私有测试数据字节不变。升级后实际检查 Pillow 13.0.0，恢复后实际检查 12.3.0，均通过。应用约 245.9 秒、恢复约 255.0 秒，仅用于这次本地验收。传输使用审计过的本地组件字节，未创建公开 Release，也没有将该结果冒称为公网下载验收。
